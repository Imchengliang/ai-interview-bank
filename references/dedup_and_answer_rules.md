# 去重判定与答案写作细则

## 一、语义去重的三步判定

对帖子里的每道题，依次问三个问题，再对照题库清单：

1. **考察点**：这题要考的是同一个知识点吗？（如「LoRA 原理」与「LoRA 的 rank 怎么选」考察点相关但不同层）
2. **提问角度**：是问「是什么／为什么」「怎么实现」「怎么选型」「出问题怎么排查」「怎么评测」中的哪一种？角度不同即视为不同题。
3. **答案是否相同**：如果把已有条目的参考答案原样搬过来能直接答这题，就是重复；若必须补充新判断、新条件或新结论，就是新题。

### 三种处置

| 判定 | 处置 | 「关联」字段 |
|------|------|--------------|
| 考察点相同 + 角度相同 + 答案相同（仅换措辞、中英互译、换例子） | 跳过，不入新编号 | — |
| 同一题的补充例子／变体问法，答案主体不变 | 并入已有条目的「题目」括注 | 无需新增，但在汇报里说明并入到哪题 |
| 角度不同／限定条件变化／明确追问或子分支 | 新增条目 | 必写相关 Q 号 + 一句差别 |

### 正反例（示意，非题库真实条目）

| 已有题 | 帖子里的新问法 | 处置 | 理由 |
|--------|----------------|------|------|
| RAG 和微调怎么选 | 什么情况下该选微调而不是 RAG | 跳过 | 同一选型题的反向措辞 |
| RAG 和微调怎么选 | RAG 检索不到相关内容时怎么排查 | 新增 | 从选型转到故障排查，答案完全不同 |
| 什么是幻觉 | 幻觉在 RAG 场景下的成因 | 新增 | 限定场景后答案不同，是母题的分支 |
| LoRA 原理 | LoRA 的 rank 怎么选、调大有什么代价 | 新增 | 参数选型这一子问题 |
| Self-Attention 为什么要除以 √d | 换成另一组维度数字问同一件事 | 跳过或并入 | 只换了例子 |
| Transformer 结构 | 手写 self-attention 的代码 | 新增，归到「编程与手撕代码」 | 从原理转到实现 |

### 边界原则

- 存疑时倾向新增，并写清关联；漏记一个分支比多记一条更难补救。
- 但不要为了显得有产出，把一道大题强行拆成多个编号；只有当每个子问确实需要不同答案时才拆。
- 一个类别都没有合适归处时，优先找最接近的类别；13 类实在装不下才新增类别，并在更新日志写明原因。

## 二、答案写作规范

### 长度与语气

- 每题「考什么 + 解题思路 + 参考答案」合计约 150–250 字，硬上限 350 字。
- 用面试口语：能直接念出来，短句为主，不写论文腔。
- 重点是「思路清晰」，不是「信息量大」。宁可少讲一个延伸知识点，也不要铺成教程。

### 三段各自的任务

| 段落 | 写什么 | 不写什么 |
|------|--------|----------|
| 考什么 | 一句话点破面试官真正想确认的能力（如「想看你能否区分检索失败和生成失败」） | 不复述题干 |
| 解题思路 | 2–4 步：先判断什么 → 再分哪几种情况 → 最后怎么收口 | 不列公式推导、不写背景历史 |
| 参考答案 | 3–6 句可直接口述的结论 + 必要的一两个关键理由 | 不堆术语、不引论文、不列长清单 |

### 关联如何点

- 只在确有必要时点一句，格式：`和 Q0xx 的差别在于：那题问的是……，这题多了……条件。` 或 `这题是 Q0xx 在……场景下的分支。`
- 不重复展开关联题的答案；需要读者自行跳转。
- 若关联题还是「待分析」，照常写关联，不等待。

### 禁止

- 编造具体指标数字、论文结论、公司内部做法；不确定时写「面试里可以说明不确定，并给出验证思路：……」。
- 大段公式、架构图、代码；确需代码时给 3 行以内伪代码或一句话描述。
- 把答案写成「首先介绍背景……」的长篇科普。
- 用「视情况而定」当结论；要给判断依据。

## 三、帖子自带参考答案的处理

小红书帖子常同时给出「题目 + 参考答案／解析」。原帖答案定位为**校验素材**，不是答案来源。

顺序不可颠倒：

1. 读帖时把题目与参考答案分开记录；答案素材只留在当批上下文里，不写入题库条目。
2. 先独立按「考什么 → 解题思路 → 参考答案」写出自己的版本，并把状态改为「已分析」。
3. 写完后才对照原帖答案，只做三件事：
   - **补漏**：自己漏掉的关键判断点，用一句话补进思路或答案；
   - **纠错**：原帖明显错误、过时或以偏概全的说法不跟随；若面试中容易踩坑，在参考答案里用一句话点明；
   - **分支识别**：原帖答案展开了一个不同角度或子问题，回到第一节的去重规则判断是否需要新增题目。
4. 对照后仍受同样的字数与风格约束；不因为原帖答案长就写长。

禁止：

- 直接复制、轻度改写或拼接原帖答案充当 `**参考答案**`。
- 把原帖答案里的长篇背景、公式推导、论文引用带进题库。
- 默认「原帖写得多 = 更权威」；有疑问时按自己的判断写，并说明验证思路。

## 四、完整示例（格式示范，非题库真实条目）

```markdown
#### Q014 · RAG 与知识增强 · 状态：已分析
**题目**：RAG 检索不到相关内容时怎么排查？
**关联**：Q003（RAG 与微调选型，那题讲怎么选，这题讲选完之后出错怎么定位）

**考什么**：想看你能否把「检索失败」和「生成失败」分开定位，而不是笼统说调 prompt。

**解题思路**
1. 先看召回：拿 query 直接检索，命中的 chunk 是否真的不含答案；不含就是切分或 embedding 的问题。
2. 再看排序：答案在候选里但排在后面，属于 top-k 或 rerank 的问题。
3. 最后看生成：上下文里已有答案仍答错，才是 prompt 或模型的问题。

**参考答案**：我会按链路分段排查。先用原始 query 单独跑检索，看答案所在片段有没有被召回；没有就检查切分粒度和 embedding，必要时加关键词混合检索。如果片段召回了但排得靠后，就调 top-k 或加重排。只有确认上下文里确实有答案模型还答错，才会去改 prompt 或换模型。这样能避免一上来就调 prompt 却没解决根因。
```
